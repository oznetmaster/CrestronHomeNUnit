All 34 language/async-lifecycle compatibility tests passed twice in each environment. Processor compatibility and framework runs all used one host PID, without reloading between rounds. The host ran tests serially (`NumberOfTestWorkers=0`). Upstream invalid discovery nodes were retained by the diagnostic-only packaging option; they are not passing test results.

The two unmerged Windows failures concern async-void rejection and the framework's facade-qualified attribute lookup. Merged Windows adds compiler/reference-environment failures. The processor's four first-round failures are two `/temp` file-existence checks and two compiler tests that see internalized NUnit types rather than the public reference surface. The second round adds five cases whose static mutable ordering constraints were reused. No disposed-wait-handle failure recurred. Warnings and skips are reported separately from passing tests.

These observations establish specific limits of this unchanged upstream diagnostic harness. They do not establish a general NUnit or Mono defect. The separate production suite is adapted as described in [its provenance](../../vendor/nunit/PROVENANCE.md); do not substitute its results for this diagnostic baseline.
